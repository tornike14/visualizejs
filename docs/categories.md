# Categories

Topics are grouped into categories. Everything that depends on a category (label, route, colours, hero copy, SEO keywords, sidebar toggle, landing page sections, sitemap) reads from one registry.

**File:** `src/lib/categories.ts`

## Current Categories

| ID           | Label      | Route         | Accent  |
| ------------ | ---------- | ------------- | ------- |
| `javascript` | JavaScript | `/javascript` | yellow  |
| `react`      | React      | `/react`      | cyan    |
| `frameworks` | Frameworks | `/frameworks` | emerald |
| `backend`    | Backend    | `/backend`    | violet  |
| `ai`         | AI         | `/ai`         | pink    |

`CATEGORY_ORDER` controls the order in the sidebar toggle, the landing page, and the sitemap.

## CategoryConfig Fields

| Field                                                                                               | Used by                                                                       |
| --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `label`, `headingLabel`                                                                             | Page titles, sidebar, breadcrumbs, structured data                            |
| `route`                                                                                             | Links, sitemap, `categoryFromPathname`                                        |
| `tagline`, `description`, `kicker`, `indexTitle`                                                    | Landing page sections, category hero, category metadata                       |
| `iconSrc`, `iconAlt`, `iconShellClass`                                                              | Sidebar toggle, landing page, hero                                            |
| `docsLabel`                                                                                         | The external docs link label in the theory section ("on MDN", "on react.dev") |
| `titleAccentClass`, `kickerClass`, `toggleActiveClass`, `badgeClass`, `ctaClass`, `glowRgb`, `hero` | Colours. Keep one hue per category                                            |
| `keywords`                                                                                          | Merged into every topic's SEO keywords in that category                       |
| `indexKeywords`                                                                                     | Keywords of the category index page                                           |

## Adding a Category

1. Add the ID to the `Category` union in `src/types/index.ts`.
2. Add a `CategoryConfig` entry to `CATEGORIES` and the ID to `CATEGORY_ORDER` in `src/lib/categories.ts`.
3. Add an icon at `public/icons/<id>.svg` (48x48 viewBox, single colour family).
4. Create `src/content/theory/<id>/` for theory files.
5. Add at least one topic (see `docs/topic-authoring.md`). Empty categories still render a hero with no cards.
6. Run `npm run verify`.

Nothing else needs to change. The category page is generated by `src/app/[category]/page.tsx`, and the sidebar, search palette, landing page, sitemap, metadata, and page shell all iterate over `CATEGORY_LIST`.

## Helpers

```typescript
import {
  CATEGORIES,
  CATEGORY_LIST,
  getCategory,
  categoryFromPathname,
} from "@/lib/categories";

CATEGORIES.ai.label; // "AI"
CATEGORY_LIST.map((c) => c.route); // ["/javascript", "/react", ...]
categoryFromPathname("/backend/jwt-authentication"); // "backend"
```

Never branch on `category === "javascript"` in components. Read the field you need from the config instead.

## Topic Groups

A topic can carry `group: "Vue"` (any label) in `src/lib/topics.ts`. The category page and the sidebar then list topics under that heading, in first-appearance order, with ungrouped topics first. Frameworks uses this to keep Vue, Svelte, and Angular apart; the other categories are flat.

## Frameworks Roadmap

Frameworks has one topic per framework today. The category is meant to reach two or three per framework plus a few cross-framework comparisons. Candidates, in rough priority:

| Group      | Topic                      | What it shows                                                                                    |
| ---------- | -------------------------- | ------------------------------------------------------------------------------------------------ |
| Vue        | Computed and Watchers      | Lazy computed caching vs eager watchers, and when each re-runs                                   |
| Vue        | Template Compilation       | A template becoming a render function with patch flags, and why block trees skip static nodes    |
| Svelte     | Stores and Context         | Writable, derived, and readable stores, subscriptions, and how `$store` compiles                 |
| Svelte     | Compiler Output            | Side by side: one component, the generated `$.template` and effect code                          |
| Angular    | Dependency Injection       | Injector tree lookup, `providedIn`, and why the same token can resolve to different instances    |
| Angular    | RxJS in Templates          | The `async` pipe, subscription lifetime, and change detection triggered by emissions             |
| Solid      | Fine-Grained Signals       | createSignal and createEffect without a component re-render model, for contrast with React       |
| Comparison | Reactivity Models Compared | The same counter in React, Vue, Svelte, Solid, and Angular, showing what re-executes on a change |

Each one follows `docs/topic-authoring.md`. Add `group` to the registry entry so it lands under the right heading.
